The solution

The solution in three parts

1 · Order of unfolding

The order in which features are shown to the user, set by value analysis

2 · Supporting UI components

Tooltips, milestones and guided tours built on the Nutanix design system

3 · The onboarding flow

The full journey for users with or without data, and for advanced users

Solution 1 · Order of unfolding

Which feature to show first? A value analysis

I ranked every feature on three criteria with a weighted matrix, and did the same for supporting features.

Ease of task execution

Effort reduction

Usage frequency

Resulting order: primary features

  1. Onboard a cloud resource
  2. Dashboard
  3. Findings & alerts
  4. Inventory
  5. Compliance
  6. Security planning

Then, optional

Scope, custom audits, rules, audit policy, integrations, threat detection, reports, history

Solution 2 · Supporting UI components

Information tooltips and milestone moments

Basic information tooltips, with variants for milestone completion and visual guides on actions, all within the existing Nutanix design system.

Solution 2 · Supporting UI components

Solution 2 · Supporting UI components

Competitor analysis

Every FTUE framework I read covers three things. I checked 15 products against them, most picked from articles on onboarding best practice.

1. Strategies

Help, contextual onboarding, progressive disclosure, assistance-based onboarding, degree of user control, documentation & support

2. Order of unfolding

A user-value-based flow, a function-based flow, or a feature-based flow

3. UI elements

Sign-up, welcome message, product tours, progress bar, checklists, hotspots, action-driven tooltips, milestone celebration, in-app & out-of-app connection, ending message

What the competitors taught me

Tour initiation

Skippable tours, a gist of the contents, mock images to explain features

Advanced use

Access to help, jumping to a point in a tour, learnable new features

Attention grabbers

Animated point and label hotspots, with the right colour and contrast

Information delivery

Context-based tooltips; progress, back, skip and next controls

Encouragement

Subtle celebrations using image and text increase engagement

Help initiation

A visible floating icon, and tours you can start any time

Ending directions

A short sum-up, a celebration, and where to go next

Defining the must-haves

What the research showed

  • Show users what they can do and what to expect
  • Deliver value as soon as possible, with minimum effort
  • Make things clear, visible and easy to learn
  • Encourage users to investigate the options
  • Give users a reason to come back

User persona

Alex, VI & IT security admin

35 · 10+ years in IT infrastructure and cybersecurity · Bangalore · Uses CloudHealth, Prisma Cloud, CloudCheckr

Goals

  • Ensure compliance across on-premises and cloud resources
  • Real-time visibility into the security posture
  • Keep cloud resources in good health

Pain points

  • Scaling security across hybrid cloud environments
  • Finding and fixing vulnerabilities efficiently
  • Balancing efficiency with strict compliance

Qualities

  • Tech-savvy, often switching between dashboards
  • Prefers streamlined tools with actionable insights
  • Relies on reports for audits and stakeholders

Wants

  • One dashboard for multi-cloud security
  • Automated vulnerability detection and remediation
  • Real-time compliance tracking and easy reports

The major user needs

01

Show the product’s value as soon as possible

02

Handle the wait time and errors after linking a cloud

03

Motivate users to onboard cloud resources

04

Clear navigation, and access to help

For first-time use

  • Redesign the end-to-end user flow
  • Where to go next once a cloud resource is onboarded
  • Handle the waiting time of onboarded resources
  • Show value with dummy data, and introduce every feature

For advanced use

  • Access to help
  • Jump between tours to a specific point
  • Visibility and learnability of new features

What testing surfaced

6 people · 2nd round of prototype testing

Co-creation sessions

  • Options flickered position during the product tour
  • The login and first screens looked almost the same
  • Tooltips overlapped the background screenshots
  • Dummy-data and real-data tour CTAs could be confused
  • The first screen lacked motivation
4 people · 3rd round of prototype testing

Manager reviews

  • Set expectations for how long a resource takes to onboard; users kept raising requests about it
  • Show what to do next after onboarding, on the dashboard
  • Give advanced users access to help
  • Check how network traffic and inventory data each populate
